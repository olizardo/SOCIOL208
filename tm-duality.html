The Duality of Persons and Groups

  • Show All Code
  • Hide All Code
  • View Source

Recall that in the one-mode case, multiplying the adjacency matrix times its transpose yields the common neighbors matrix \(\mathbf{M}\):

\[ \mathbf{M} = \mathbf{A}\mathbf{A}^T \]

As famously noted by Breiger (1974), doing the same for the affiliation matrix of a two-mode network also returns the common-neighbors matrix, but because objects in one mode can only connect to objects in the other mode, that means that the “common neighbors” of people have to be sets of groups and the common neighbors of groups have to be sets of people. This reveals the duality of persons and groups: Indirect connections between people are made up of the groups they share, and indirect connections between groups are composed of the people they share.

1 The Two-Mode Common Neighbors Matrices

1.1 The Dual Projections

In short, computing the common neighbors matrix for both people and groups, also called the projection of the two-mode network into each mode, yields a one-mode similarity matrix between people and groups, where similarity is defined by the number of objects they share in the other mode.

For the people, the relevant projection is:

\[ \mathbf{P} = \mathbf{A}\mathbf{A}^T \tag{1}\]

And for the groups:

\[ \mathbf{G} = \mathbf{A}^T\mathbf{A} \tag{2}\]

Interestingly, as noted by Faust (1997, 167), there is a (dual!) mathematical connection between the strength of each vertex in the weighted projection and the centrality of the nodes from the other set they are connected to:

  • For people, the vertex strength is equal to the sum of the sizes of the groups they belong to minus their own degree.

  • For groups, the vertex strength is equal to the sum of the memberships of the people that belong to them, minus their own size.

We can verify this relationship for Evelyn:

Code 
sum.size.evelyn <- sum(A["Evelyn", ] * degree(g)[which(V(g)$type == TRUE)]) # sum of the sizes of the groups Evelyn belongs to
sum.size.evelyn - degree(g)[which(V(g)$name == "Evelyn")]
Evelyn 
    50

Which is indeed Evelyn’s vertex strength.

Dually, the same relation applies to groups:

Code 
sum.mem.6.27 <- sum(A[, "6/27"] * degree(g)[which(V(g)$type == FALSE)]) # sum of the memberships of people in the first group
sum.mem.6.27 - degree(g)[which(V(g)$name == "6/27")]
6/27 
  19

This is indeed the vertex strength of the event held on 6/27.

2 Visualizing Dual Projections Using the Maximum Spanning Tree

As we saw, projecting the original biadjacency matrix using Breiger’s (1974) approach yields two weighted one-mode networks. Because an edge exists between two persons (groups) if they share at least one person (group), the resulting graphs tend to be dense, with high connectivity between nodes, as in Figure 1. This can make it hard to discern the connectivity structure of the projected networks and detect patterns.

One approach to simplifying the visual projections of two-mode networks is to compute a spanning tree of the resulting weighted graph. For any weighted network, a spanning tree is a graph that connects all nodes using exactly \(N-1\) edges, where \(N\) is the number of nodes, and contains no cycles.1

Because the edge weights in the projection encode tie strength rather than cost or distance, the tree we want is the maximum spanning tree: among all spanning trees of the projection, the one that keeps the largest possible total tie strength. This gives us the backbone of strongest ties running through the projected network, rather than the backbone of weakest ties that a cost-oriented minimum spanning tree would return.

To do this, we can follow Kruskal’s Algorithm, with one change: because we want the maximum spanning tree, we sort edges from strongest to weakest rather than weakest to strongest. Kruskal’s greedy procedure is otherwise identical:

  • First, we create an edge list containing each of the edge weights of the one-mode projection graph.
  • Then we sort the edge list by weight in decreasing order (largest weights first).
  • Then, we create an undirected empty graph with \(N\) nodes.
  • Now, we go down the edge list, adding edges to the empty graph one at a time, at each step checking that:
    1. We are not connecting nodes that have already been connected (avoiding multiedges).
    2. Additional edges do not create cycles (as the resulting graph would no longer be a tree).

We stop when we have the desired number of edges (\(N-1\)), meaning all nodes are connected in the tree.

Note that this is exactly the standard minimum-spanning-tree version of Kruskal’s algorithm run on inverted distances \(d_{ij} = 1/w_{ij}\) (as built-in implementations such as mst(G.p, weights = 1 / E(G.p)$weight) do under the hood), since both induce the same edge ordering. Working directly with the original weights keeps them in their natural shared-membership interpretation.

Here’s a function that does all of this, taking the weighted projection igraph object as input and returning the maximum spanning tree:

Code 
make.max.st <- function(x) {
  edgelist <- data.frame(as_edgelist(x), w = E(x)$weight) # creating weighted edge list
  edgelist <- edgelist[order(edgelist$w, decreasing = TRUE), ] # ordering by edge weight (largest first)
  Tr <- make_empty_graph(n = vcount(x), directed = FALSE) # creating empty graph
  V(Tr)$name <- V(x)$name
  k <- 1
  n.e <- ecount(Tr)
  n.v <- vcount(Tr) - 1
  while (n.e < n.v) {
    if (k > nrow(edgelist)) { # guard: projection is disconnected
      stop("Graph is disconnected: no spanning tree exists.")
    }
    i <- match(edgelist[k, 1], V(x)$name) # vertex id of first endpoint
    j <- match(edgelist[k, 2], V(x)$name) # vertex id of second endpoint
    if (!are_adjacent(Tr, i, j)) { # checking nodes are not adjacent
      Tr <- add_edges(Tr, c(i, j)) # add edge
      n.e <- ecount(Tr) # new edge id
      if (!is_acyclic(Tr)) { # checking new edge does not add a cycle
        Tr <- delete_edges(Tr, n.e) # delete edge if it adds a cycle
      }
    }
    n.e <- ecount(Tr)
    k <- k + 1
  }
  return(Tr)
}

We can now build the maximum spanning tree graph for each weighted projection:

Code 
Tr.p <- make.max.st(G.p)
Tr.g <- make.max.st(G.g)

3 An Asymmetric Approach to Weighted Projection

Zhou et al. (2007) describe an asymmetric approach to projecting a two-mode network into two one-mode weighted networks, which addresses two limitations of the Breiger projections computed earlier:

  • First, there is the fact that the standard projection always results in a symmetric weighted adjacency matrix.

  • Secondly, the fact that edges incident to degree-one nodes lose all their information in the traditional projection of the opposite mode, as a group with a single member creates no person-person ties in the person projection, and a person with a single membership creates no group-group ties in the group projection.

3.1 The Weighting Scheme

Formally, in Zhou et al. (2007)’s approach, each entry of the person projection matrix is computed by summing over the groups two people share, but instead of counting each shared group as one point, we weigh it by the group’s degree and the other person’s degree.

So if \(\mathbf{k}^p\) is the degree vector of the people, \(\mathbf{k}^g\) is the degree vector of the groups, and \(m\) is the total number of groups, then the entry \(p_{ij}\) of the weighted person projection matrix is computed as:

\[ p_{ij} = \sum_{l=1}^{m} \frac{a_{il}a_{jl}}{k^p_j k^g_l} \tag{3}\]

The numerator of this equation counts the total number of memberships shared by persons \(i\) and \(j\) as \(a_{il}a_{jl}= 1\) only when group \(l\) is shared between persons \(i\) and \(j\), but the denominator weights each shared membership by the number of memberships of person \(j\) and the size of the shared group \(l\). The intuition is that if person \(j\) belongs to many groups, sharing a group with them is less meaningful for \(i\); similarly, if group \(l\) has many members, sharing that group with another person is also less meaningful.

On the group side, the entry \(g_{ij}\) of the weighted group projection matrix is computed similarly:

\[ g_{ij} = \sum_{l=1}^{n} \frac{a_{li}a_{lj}}{k^g_j k^p_l} \tag{4}\]

Where \(n\) is the total number of people, and the intuition is the same as for the person projection. If group \(j\) has many members, sharing a member matters less from group \(i\)’s perspective; similarly, if the person \(l\) they share belongs to many groups, sharing them should matter less.

3.2 Computing the Weighted Projections

Let’s compute these projections in R by defining a function that implements the formulas above:

Code 
# Function to compute the weighted person projection
zhou.proj <- function(A) {
  k_p <- rowSums(A) # degree vector of people
  k_g <- colSums(A) # degree vector of groups     
  m <- ncol(A) # total number of groups
  n <- nrow(A) # total number of people   
  P.w <- matrix(0, nrow = nrow(A), ncol = nrow(A)) # initialize person projection matrix
  for (i in 1:nrow(A)) {
    for (j in 1:nrow(A)) {
      P.w[i, j] <- sum((A[i, ] * A[j, ]) / (k_p[j] * k_g)) # compute entry p_ij
    }
  }
  G.w <- matrix(0, nrow = ncol(A), ncol = ncol(A)) # initialize group projection matrix   
  for (i in 1:ncol(A)) {
    for (j in 1:ncol(A)) {
      G.w[i, j] <- sum((A[, i] * A[, j]) / (k_g[j] * k_p)) # compute entry g_ij
    }
  }
  rownames(P.w) <- colnames(P.w) <- rownames(A) # set row and column names for person projection
  rownames(G.w) <- colnames(G.w) <- colnames(A) # set row and column names for group projection
  return(list("P.w" = P.w, "G.w" = G.w))
}

3.3 The Matrix Formulation

Note that we can also express the Zhou et al. (2007) projection in matrix notation. If \(\mathbf{A}\) is the biadjacency matrix, \(\mathbf{D}_p\) is the diagonal degree matrix of the people, and \(\mathbf{D}_g\) is the diagonal degree matrix of the groups, then the weighted person projection matrix \(\mathbf{P}\) and the weighted group projection matrix \(\mathbf{G}\) can be computed as:

\[ \mathbf{P} = \mathbf{A} \mathbf{D}_g^{-1} \mathbf{A}^T \mathbf{D}_p^{-1} \tag{5}\]

\[ \mathbf{G} = \mathbf{A}^T \mathbf{D}_p^{-1} \mathbf{A} \mathbf{D}_g^{-1} \tag{6}\]

Where \(\mathbf{D}_p^{-1}\) and \(\mathbf{D}_g^{-1}\) are the inverses of the diagonal degree matrices of the people and groups, respectively. This matrix formulation allows for more efficient computation of the projections, especially for larger networks, as it leverages matrix operations instead of nested loops. We can compute the person projection using this matrix formulation as follows:

Recall that in the [one-mode case](prest-hits.qmd), multiplying the adjacency matrix times its transpose yields the **common neighbors matrix** $\mathbf{M}$:

$$
\mathbf{M} = \mathbf{A}\mathbf{A}^T
$$

As famously noted by @breiger74, doing the same for the affiliation matrix of a two-mode network also returns the common-neighbors matrix, but because objects in one mode can only connect to objects in the other mode, that means that the "common neighbors" of people have to be sets of groups and the common neighbors of groups have to be sets of people. This reveals the **duality of persons and groups**: Indirect connections between people are made up of the groups they share, and indirect connections between groups are composed of the people they share.

## The Two-Mode Common Neighbors Matrices

### The Dual Projections

In short, computing the common neighbors matrix for both people and groups, also called the **projection** of the two-mode network into each mode, yields a one-mode similarity matrix between people and groups, where similarity is defined by the number of objects they share in the other mode. 

For the people, the relevant projection is:

$$
\mathbf{P} = \mathbf{A}\mathbf{A}^T
$$ {#eq-p}

And for the groups:

$$
\mathbf{G} = \mathbf{A}^T\mathbf{A}
$$ {#eq-g}

## Visualizing Dual Projections Using the Maximum Spanning Tree

As we saw, projecting the original biadjacency matrix using Breiger's [-@breiger74] approach yields two weighted one-mode networks. Because an edge exists between two persons (groups) if they share at least one person (group), the resulting graphs tend to be dense, with high connectivity between nodes, as in @fig-projection. This can make it hard to discern the connectivity structure of the projected networks and detect patterns.

One approach to simplifying the visual projections of two-mode networks is to compute a **spanning tree** of the resulting weighted graph. For any weighted network, a spanning tree connects all nodes using exactly $N-1$ edges, where $N$ is the number of nodes, and contains no cycles.^[Recall that a tree is a connected graph without any cycles.]

Because the edge weights in the projection encode tie *strength* rather than cost or distance, we want the **maximum spanning tree**: among all spanning trees of the projection, the one that maximizes total tie strength. This gives us the backbone of strongest ties running through the projected network, rather than the backbone of weakest ties that a cost-oriented minimum spanning tree would return.

To do this, we can follow **Kruskal's Algorithm**, with one change: because we want the maximum spanning tree, we sort edges from strongest to weakest rather than weakest to strongest. Kruskal's greedy procedure is otherwise identical:

- First, we create an edge list containing each of the edge weights of the one-mode projection graph.
- Then we sort the edge list by weight in decreasing order (largest weights first).
- Then, we create an undirected empty graph with $N$ nodes.
- Now, we go down the edge list, adding edges to the empty graph one at a time, at each step checking that:
  1. We are not connecting nodes that have already been connected (avoiding **multiedges**).
  1. Additional edges do not create **cycles** (as the resulting graph would no longer be a tree). 

We stop when we have the desired number of edges ($N-1$), meaning the tree connects all nodes.

Note that this is exactly the standard minimum-spanning-tree version of Kruskal's algorithm run on inverted distances $d_{ij} = 1/w_{ij}$ (as built-in implementations such as `mst(G.p, weights = 1 / E(G.p)$weight)` do under the hood), since both induce the same edge ordering. Working directly with the original weights keeps them in their natural shared-membership interpretation.

Here's a function that does all of this, taking the weighted projection `igraph` object as input and returning the maximum spanning tree:

```{r}
make.max.st <- function(x) {
  edgelist <- data.frame(as_edgelist(x), w = E(x)$weight) # creating weighted edge list
  edgelist <- edgelist[order(edgelist$w, decreasing = TRUE), ] # ordering by edge weight (largest first)
  Tr <- make_empty_graph(n = vcount(x), directed = FALSE) # creating empty graph
  V(Tr)$name <- V(x)$name
  k <- 1
  n.e <- ecount(Tr)
  n.v <- vcount(Tr) - 1
  while (n.e < n.v) {
    if (k > nrow(edgelist)) { # guard: projection is disconnected
      stop("Graph is disconnected: no spanning tree exists.")
    }
    i <- match(edgelist[k, 1], V(x)$name) # vertex id of first endpoint
    j <- match(edgelist[k, 2], V(x)$name) # vertex id of second endpoint
    if (!are_adjacent(Tr, i, j)) { # checking nodes are not adjacent
      Tr <- add_edges(Tr, c(i, j)) # add edge
      n.e <- ecount(Tr) # new edge id
      if (!is_acyclic(Tr)) { # checking new edge does not add a cycle
        Tr <- delete_edges(Tr, n.e) # delete edge if it adds a cycle
      }
    }
    n.e <- ecount(Tr)
    k <- k + 1
  }
  return(Tr)
}
```

We can now build the maximum spanning tree graph for each weighted projection:

```{r}

```

## An Asymmetric Approach to Weighted Projection

@zhou_etal07 describe an asymmetric approach to projecting a two-mode network into two one-mode weighted networks, which addresses two limitations of the Breiger projections computed earlier:

- First, there is the fact that the standard projection always results in a *symmetric* weighted adjacency matrix.

- Secondly, the fact that edges incident to degree-one nodes lose all their information in the traditional projection of the *opposite* mode, as a group with a single member creates no person-person ties in the person projection, and a person with a single membership creates no group-group ties in the group projection.

### The Weighting Scheme

Formally, in @zhou_etal07's approach, each entry of the person projection matrix is computed by summing over the groups two people share, but instead of counting each shared group as one point, we weigh it by the group's degree and the *other person's* degree.

So if $\mathbf{k}^p$ is the degree vector of the people, $\mathbf{k}^g$ is the degree vector of the groups, and $m$ is the total number of groups, then the entry $p_{ij}$ of the weighted person projection matrix is computed as:

$$
p_{ij} = \sum_{l=1}^{m} \frac{a_{il}a_{jl}}{k^p_j k^g_l}
$${#eq-zhou1}

The numerator of this equation counts the total number of memberships shared by persons $i$ and $j$ as $a_{il}a_{jl}= 1$ only when group $l$ is shared between persons $i$ and $j$, but the denominator weights each shared membership by the number of memberships of person $j$ and the size of the shared group $l$. The intuition is that if person $j$ belongs to many groups, sharing a group with them is less meaningful for $i$; similarly, if group $l$ has many members, sharing that group with another person is also less meaningful.

On the group side, the entry $g_{ij}$ of the weighted group projection matrix is computed similarly:

$$
g_{ij} = \sum_{l=1}^{n} \frac{a_{li}a_{lj}}{k^g_j k^p_l}
$${#eq-zhou2}

Where $n$ is the total number of people, and the intuition is the same as for the person projection. If group $j$ has many members, sharing a member matters less from group $i$'s perspective; similarly, if the person $l$ they share belongs to many groups, sharing them should matter less.

### Computing the Weighted Projections

Let's compute these projections in R by defining a function that implements the formulas above: 

```{r}
# Function to compute the weighted person projection
zhou.proj <- function(A) {
  k_p <- rowSums(A) # degree vector of people
  k_g <- colSums(A) # degree vector of groups     
  m <- ncol(A) # total number of groups
  n <- nrow(A) # total number of people   
  P.w <- matrix(0, nrow = nrow(A), ncol = nrow(A)) # initialize person projection matrix
  for (i in 1:nrow(A)) {
    for (j in 1:nrow(A)) {
      P.w[i, j] <- sum((A[i, ] * A[j, ]) / (k_p[j] * k_g)) # compute entry p_ij
    }
  }
  G.w <- matrix(0, nrow = ncol(A), ncol = ncol(A)) # initialize group projection matrix   
  for (i in 1:ncol(A)) {
    for (j in 1:ncol(A)) {
      G.w[i, j] <- sum((A[, i] * A[, j]) / (k_g[j] * k_p)) # compute entry g_ij
    }
  }
  rownames(P.w) <- colnames(P.w) <- rownames(A) # set row and column names for person projection
  rownames(G.w) <- colnames(G.w) <- colnames(A) # set row and column names for group projection
  return(list("P.w" = P.w, "G.w" = G.w))
}     
```

Now we can apply this function to our biadjacency matrix `A` to get the weighted person and group projections: 

```{r}

P.w <- projections$P.w # weighted person projection
G.w <- projections$G.w # weighted group projection
round(P.w[1:5, 1:5], 3) # view the first 5 rows and columns of the person projection
round(G.w[1:5, 1:5], 3) # view the first 5 rows and columns of the group projection
```

The @zhou_etal07 approach produces two *asymmetric* weighted adjacency matrices for the person and group projections, which can be used for analyses such as clustering, centrality, or visualization. The key advantage is that it accounts for node degrees in the other mode, providing a better representation of relationships in the two-mode network.

### The Matrix Formulation

We can also express the @zhou_etal07 projection in matrix notation, as with the standard Breiger projection. If $\mathbf{A}$ is the biadjacency matrix, $\mathbf{D}_p$ is the diagonal degree matrix of the people, and $\mathbf{D}_g$ is the diagonal degree matrix of the groups, then the weighted person projection matrix $\mathbf{P}$ and the weighted group projection matrix $\mathbf{G}$ can be computed as:

$$
\mathbf{P} = \mathbf{A} \mathbf{D}_g^{-1} \mathbf{A}^T \mathbf{D}_p^{-1}
$$ {#eq-zhou3}

$$
\mathbf{G} = \mathbf{A}^T \mathbf{D}_p^{-1} \mathbf{A} \mathbf{D}_g^{-1}
$$ {#eq-zhou4}

Here, $\mathbf{D}_p^{-1}$ and $\mathbf{D}_g^{-1}$ are the inverses of the diagonal degree matrices for people and groups, respectively. Thus, the Zhou projection is the projection of the group-degree-weighted original biadjacency matrix and the person-degree transpose of the biadjacency matrix.^[This matrix formulation enables more efficient computation of the projections, especially for larger networks, by leveraging matrix operations instead of nested loops.] 

In `R`, we can compute the person projection using this matrix formulation as follows:

```{r}
P.w <- A %*% diag(1 / colSums(A)) %*% t(A) %*% diag(1 / rowSums(A)) # diagonal rescaling, cheaper than inverting via solve()
colnames(P.w) <- rownames(P.w) <- rownames(A) # set row and column names for person projection

G.w <- t(A) %*% diag(1 / rowSums(A)) %*% A %*% diag(1 / colSums(A))
colnames(G.w) <- rownames(G.w) <- colnames(A) # set row and column names for group projection

round(P.w[1:5, 1:5], 3) # view the first 5 rows and columns of the person projection
round(G.w[1:5, 1:5], 3) # view the first 5 rows and columns of the group projection
```

As you can see, this gives the same result as the nested-loop implementation.

### Resource Conservation and Asymmetry

A key signature of the @zhou_etal07 projection matrices is that each column sums to one (the matrices are **column-stochastic**; the basic idea is that every node (e.g., a person) ``sends'' some proportion of their fixed membership budget to another person with which they share a group. Obviously, people with many  memberships spread this budget across many memberships, so they have less to share; people with few memberships have  more to share, so they send more to their projection neighbors. 

```{r}

colSums(G.w) # each column should sum to one
```

As promised, the entries of the person and group projection matrices are not symmetric, so $p_{ij} \neq p_{ji}$ and $g_{ij} \neq g_{ji}$ in general. This is because the weighting scheme accounts for the degree of the column node and the degree of the shared nodes in the other mode, so the ratio of the two directed weights between any pair of nodes is fixed by their degree ratio ($p_{ij}/p_{ji} = k^p_i/k^p_j$ in @zhou_etal07's Equation 7).

We can check this formally using the base `R` function `isSymmetric`:

